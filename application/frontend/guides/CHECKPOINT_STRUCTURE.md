# Understanding Your DiscoveryAgent Output

This guide explains the files and directories that DiscoveryAgent creates during a research run. It will help you find specific results, understand which reports matter, and know where to look when reviewing the agent's work.

## What Gets Created

Every run produces two directories:

1. **The code directory** — where the agent writes code, downloads data, and saves figures
2. **The checkpoint directory** — where the agent records its reasoning, reports, and checkpoints

```
Log directory:
  ├── checkpoints/            Research trace (reports, hypotheses, queries)
  ├── deep_research_background.md   Literature survey
  ├── ai_researcher.log             Detailed activity log
  └── searches/                     Web search results
```

The **project directory** is where you'll find the actual outputs of the research — the data, code, and figures. The **log directory** is where you'll find the research narrative — what the agent investigated, what it found, and how it reasoned about its findings.

---

## The Checkpoint Directory

The `checkpoints/` directory is organized by **rounds**. Each round represents one full cycle of hypothesis selection and investigation.

```
checkpoints/
├── config.yaml                  How the run was configured
├── reviewer_prompt.md           Criteria used to evaluate research quality
├── round_0/
│   ├── selected_hypothesis.md   What was investigated this round
│   ├── query_001/               First research step
│   │   └── query_001.md         What the agent did and found
│   ├── query_002/               Second research step
│   │   └── query_002.md
│   ├── ...
│   ├── round_report.md          Findings from this round
│   ├── round_report_summary.md  Shorter version of round findings
│   ├── memory_report.md         Accumulated findings (all rounds so far)
│   └── memory_report_summary.md Shorter version of accumulated findings
├── round_1/
│   └── ...                      Same structure
└── ...
```

## Key Files and What They Mean

### Files You'll Want to Read First

#### `round_report.md` (one per round)
The research report produced by **this round only**. This is the primary output of each round — a structured write-up of what the agent found, including:
- Background and context
- Data and methodology
- Key findings with statistical results
- References to figures and tables
- Limitations and caveats

If you want to understand what happened in a specific round, this is the file to read.

#### `memory_report.md` (one per round)
The **accumulated** report that synthesizes findings from this round *and all previous rounds*. For round 0, this is the same as the round report. For later rounds, it weaves together findings across the full investigation into a coherent narrative.

This is the file that carries knowledge forward between rounds. When the agent generates hypotheses for the next round, it reads the previous round's memory report to understand what has already been discovered.

**In short:**
- `round_report.md` = "What did we learn *this* round?"
- `memory_report.md` = "What do we know *so far* across all rounds?"

#### `round_report_summary.md` / `memory_report_summary.md`
Shorter, LLM-generated summaries of the corresponding full reports. These are useful when you want a quick overview without reading the full documents. They are generated by post-processing (not during the run itself).

---

### Per-Query Files

Within each round, there is a directory for every query the agent executed (e.g., `query_001/`, `query_002/`, etc.). Each query represents one research step — the director agent sends a task to a tool agent and records the result.

#### `query_NNN.md`
A readable summary of a single research step. Contains:
- What the agent was asked to do (the query)
- What it found (the result/report from the tool agent)
- Relevant context (the hypothesis input, timestamps)

This is the best file for understanding what happened in any individual step of the investigation.

#### `execution_agent/` (present for some queries)
When the agent ran code (downloaded data, performed statistical analyses, created visualizations), the full execution trace is saved here:
- **`transcript.txt`** — A readable log showing every command the agent ran, every file it read or wrote, and the outputs it received. This is the place to look if you want to verify exactly what code was executed and what results it produced.

---

### Configuration and Setup Files

#### `config.yaml`
The complete record of how the run was configured. Key settings include:
- **`num_rounds`** / **`num_queries`**: How many rounds and queries per round were allowed
- **`execution_model`** / **`director_model`** / **`hypothesis_model`**: Which LLMs were used for each role
- **`human_selection`**: Whether you chose hypotheses between rounds (vs. automatic selection)
- **`review_design`**: Whether an AI reviewer evaluated the agent's progress during the run
- **`dataset_name`** / **`analysis_name`**: Identifiers for this run

#### `config.json` (one per round)
A snapshot of configuration at the start of each round. Useful for multi-round runs where settings may change between rounds (e.g., a different hypothesis file or background report path for each round).

#### `reviewer_prompt.md`
The evaluation criteria used by the reviewer agent to assess research quality during the run. This prompt is automatically designed at the start of the run based on your dataset and task. It defines what counts as novel, rigorous, and significant work for your specific research domain.

---

### Background and Search Files

#### `deep_research_background.md`
A literature survey generated at the very start of the run. Before the agent begins any analysis, it uses web search to survey existing research related to your dataset and task. This background report provides context that informs the initial hypothesis generation.

#### `searches/round_N/`
Raw results from web and literature searches performed during each round. These are the sources the agent consulted when checking the novelty of its findings or looking up relevant methods.

---

### Reviewer Feedback

#### `reviewer_logs/review_N.md` (inside each round directory, if review was enabled)
When the reviewer is active, it periodically evaluates the agent's progress and provides feedback. This file contains all the reviewer's assessments for the round, including:
- Scores on novelty, rigor, significance, and other criteria
- Specific suggestions for improvement
- Identification of issues to fix

---

### Log Files

#### `ai_researcher.log`
The complete activity log for the entire run. Contains every prompt sent to every agent, every response received, and every action taken. This is very detailed and primarily useful for debugging or deep auditing.

#### `ai_researcher_actions.log`
A more concise log that records only key events (e.g., "hypothesis generated", "query submitted", "report saved"). Useful for getting a high-level timeline of what happened during the run.

#### `round.log` (inside each round directory)
A snapshot of the activity log at the time the round completed.

---

## How Rounds Build on Each Other

The multi-round workflow follows this cycle:

```
Round 0:
  1. Survey background literature       → deep_research_background.md
  2. Select a hypothesis to investigate  → selected_hypothesis.md
  3. Execute research queries            → query_001/ ... query_NNN/
  4. Write up findings                   → round_report.md
  5. Integrate into accumulated memory   → memory_report.md

Round 1, 2, ...:
  1. Read previous round's memory report (what we know so far)
  2. Generate new hypotheses informed by accumulated findings
  3. Select the next hypothesis           → selected_hypothesis.md
  4. Execute research queries             → query_001/ ... query_NNN/
  5. Write up findings                    → round_report.md
  6. Integrate into accumulated memory    → memory_report.md
```

Each successive round builds on what came before. The `memory_report.md` is the thread that connects rounds — it carries the accumulated knowledge forward so the agent doesn't repeat work and can build progressively deeper investigations.

## Quick Reference: Where to Find What

| I want to... | Look at... |
|---|---|
| See what hypothesis was tested | `round_N/selected_hypothesis.md` |
| Read the findings from a specific round | `round_N/round_report.md` |
| Read the accumulated findings across all rounds | `round_N/memory_report.md` (in the latest round) |
| Get a quick summary of findings | `round_N/round_report_summary.md` or `memory_report_summary.md` |
| Understand a specific analysis step | `round_N/query_NNN/query_NNN.md` |
| See exactly what code was run | `round_N/query_NNN/execution_agent/transcript.txt` |
| Check what literature was surveyed | `deep_research_background.md` |
| See reviewer feedback | `round_N/reviewer_logs/review_N.md` |
| Check how the run was configured | `config.yaml` |
| Find figures and visualizations | Project directory: `reports/figures/` |
| Find downloaded data | Project directory: `data/` |
